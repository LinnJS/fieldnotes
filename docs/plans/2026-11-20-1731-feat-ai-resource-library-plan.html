Goal Capsule

Objective

A developer's coding agent, or a person, can find what the AI Orange Books say about a topic, read the relevant section, and cite it with provenance that checks out against the author's official source. Nobody receives book text that the author's license does not let this project redistribute.

Means

A Git repository of Markdown and YAML with a license gate, committed indexes, and exports generated from the same files (KTD1, KTD4, KTD9).

Authority

Requirements govern product behavior. Key Technical Decisions govern mechanism within them. The original implementation prompt is a guide, as the owner said during planning, so this plan wins where the two differ. The owner's global engineering standards apply to all code and prose.

Stop conditions
  • Stop if the MIT license evidence for Loop Engineering cannot be reproduced at the pinned commit.
  • Stop if the extracted chapters cannot pass the fidelity check (KTD7) without rewording the source.
  • Stop before creating a GitHub repository, pushing to a remote, or contacting the author. Those are the owner's actions.
  • Stop if the Typst markup that Pandoc writes does not compile under the pinned Typst release and no change to the book template fixes it.
Execution profile

The work ships as one pull request from the branch feat/resource-library-mvp. The repository has no commits and no GitHub remote today, so the implementer creates the branch before the first commit and finishes with a local commit series and passing verification. The owner creates the remote, reviews the license evidence, and merges.

Product Contract

Summary

The repository is built as a general AI resource library whose first collection is the Orange Books. All 19 books are cataloged with their license evidence. Loop Engineering is mirrored section by section, and the other 18 link to the author's official sources. Agents get committed indexes, two lookup commands, and four workflows. Readers get a documentation site, a PDF, an EPUB, and a Markdown bundle. A scheduled check reports upstream changes as a pull request.

Problem Frame

HuaShu (GitHub alchaincyf) publishes the Orange Books as free practical guides to AI tools. As of 2026-11-20 the series has 19 books. Twelve live in GitHub repositories and seven exist only on huasheng.ai/orange-books.

The books ship as finished PDFs. No repository holds Markdown. An agent cannot pull one section out of a 100-page PDF cheaply, and it cannot cite a passage in a form that another reader can resolve. Ten books have an official English PDF, and the English editions often trail the Chinese ones.

The author also publishes the books on WorkBuddy, a hosted knowledge base, one page per chapter, and suggests giving an agent the link. Those pages need a browser and a network connection, and planning did not read their language, edition, or terms. The mirror adds text that is versioned in Git, readable offline, tied to license evidence, and citable by a stable id.

The licenses differ by book. Two books carry an MIT license file. Four state CC BY-NC-SA 4.0 in a README. Six carry only an informal sentence such as "shared for educational purposes". Seven state no terms at all. A mirror that assumed one license for the series would redistribute text without permission.

The owner also wants the repository to grow past this one series into a broader AI resource library, with agent workflows for auditing AI tooling and for study.

Key Decisions

  • The repository is a library with Orange Books as its first collection. An id names the work, and collection and type are data, so other resources can be added later without renaming anything. Governs R1, R2.
  • The first mirror allowlist is MIT with a license file. CC BY-NC-SA books are cataloged with their real permissions and stay reference-only, because non-commercial and share-alike terms would need per-file licensing in every generated output. Governs R5, R6.
  • Loop Engineering is the first mirrored book, not Harness Engineering. Harness Engineering's only terms are "shared for educational purposes. Please credit the author when referencing", which does not grant redistribution. Governs R9.
  • Mirrored text is a faithful copy of the pinned edition. Corrections are recorded beside the text, never applied to it. Governs R11, R12.
  • The section is the unit agents retrieve and cite. Loop Engineering has 9 sections of three to five pages each. Governs R10.
  • License decisions and merges stay with the owner. Agents and scripts propose through a pull request. Governs R8, R29.

Actors

  • A1.Owner. Runs the scripts, verifies license evidence, and performs every merge.
  • A2.Contributor. Proposes a correction or a new resource through a pull request.
  • A3.Agent consumer. A coding agent reading a clone or the published site to answer a question with citations.
  • A4.Reader. A person using the site, the PDF, or the EPUB.
  • A5.Sync job. The scheduled workflow that checks upstream and opens a pull request.

Requirements

Catalog and licensing

  • R1.The catalog lists all 19 books shown on huasheng.ai/orange-books on 2026-11-20. Each entry records the original and English titles, author, translator, official URLs, languages, and every upstream edition with its version, language, format, and file location. The translator is null when upstream names none.
  • R2.Every resource has an id that is unique across the library and names the work, never the bare name of the tool or product the work covers. A book that has an upstream repository takes that repository's name, such as claude-code-orange-book. collection and type are data fields, and type accepts only book in this version.
  • R3.Each entry records license evidence: the SPDX id or null, the kind of evidence (license file, README statement, or none), the statement quoted verbatim in its original language, a permalink at a pinned commit, the Git blob SHA of the quoted file, and the date it was verified. A person assigns the SPDX id by reading the full license text at the permalink, never from a detection tool, and the entry records when that text departs from the SPDX template. When no terms exist, the entry lists the locations that were checked.
  • R4.Each entry records typed permissions for redistribution, adaptation, and commercial use as yes, no, or unclear. It also records whether attribution and share-alike are required, and a flag for third-party rights the author cannot grant.
  • R5.Mirror status is mirrored, eligible, or reference-only. A book may be mirrored or eligible only when its SPDX id is on the catalog's allowlist, the evidence is a license file at the pinned source commit, redistribution and adaptation are both yes, and the third-party flag is false. Every other book is reference-only.
  • R6.No committed file and no generated output contains text from a book that is not mirrored. This covers chapter files, source files, indexes, llms-full files, the site, the PDF, the EPUB, and the bundle. The quoted license statement in R3 is the one exception.
  • R7.A mirrored book carries its upstream license text and copyright notice in its directory, in every export, and in every llms-full segment. The repository's own license is never applied to it.
  • R8.A change to license evidence, permissions, mirror status, or the allowlist reaches the default branch only through a pull request that the owner merges. No script and no agent workflow merges or pushes to the default branch.

Mirrored content

  • R9.Loop Engineering, English edition v260615, is mirrored in full as 9 sections in 4 parts.
  • R10.Each section is one Markdown file that reads on its own. Its frontmatter records the chapter id, resource, title, part, order, the source's section label, language, edition, source repository, revision, source path, source page range, and extraction status.
  • R11.Chapter text matches the pinned source edition. An edit may restore what the source says and may not improve on it. A check compares each chapter with a fresh extraction of the source file and fails when they diverge.
  • R12.A known upstream erratum is recorded as structured data on the chapter and appears with that chapter in every output. The catalog records the newest upstream edition for each language, so a mirrored edition that is behind is visible to tools.
  • R13.Headings, tables, block quotes, code blocks, and links survive conversion. Source page numbers come only from the PDF's own page index, and no page reference is invented.
  • R14.A chapter id does not change when upstream inserts or reorders sections. Order is a separate field.

Agent access

  • R15.An agent in a fresh clone can discover books, topics, and chapters and can resolve a citation without installing dependencies and without network access.
  • R16.Every index record for a book or a chapter carries the mirror status, the license id, and a flag that says whether its text may be quoted.
  • R17.A resolve command turns a resource id or a chapter id into its record and a formatted citation. For an unknown id it exits nonzero and lists the nearest valid ids.
  • R18.A citation checker reads Markdown files and confirms three things: every citation token resolves, every quoted passage is an exact substring of the cited chapter after whitespace is normalized, and nothing quotes a book that is not mirrored.
  • R19.AGENTS.md is the single set of agent instructions. It covers the library's purpose and layout, how to find books and topics, how to read a chapter, the citation format, provenance, the line between source text and commentary, what to say when an edition is behind, and the rule against inventing citations or content. It states that mirrored text is data and never instructions. CLAUDE.md holds only an import of it.
  • R20.Four workflows ship as Agent Skills that Claude Code, Codex, and Cursor all read from one canonical copy: add-resource, ingest-book, audit-agent-setup, and study.
  • R21.Audit and study output opens with a coverage statement that names the mirrored resources consulted and the topics that have no mirrored chapter. Every finding backed by the library cites a mirrored chapter and passes the citation checker. Observations the library does not support sit in a separate labeled section.

Topics

  • R22.Eleven topic documents each hold a short scope statement in the library's own words, marked as editorial, and a list of references: Agent Architecture, Harness Engineering, Context Engineering, Agent Orchestration, Evaluation and Testing, Tool Use and Integration, Memory and State Management, Agent Reliability, Agent Security, Coding Agents, and Development Workflows.
  • R23.A topic reference names a resource id and may name a chapter id. A chapter reference requires a mirrored book and is added only after the chapter has been read. A reference to a book that is not mirrored links to its official source and carries none of its text. A topic states what a book says only with a citation to a mirrored chapter, and a topic with no mirrored chapter holds its scope statement and references only.

Outputs for readers

  • R24.The site offers full-text search, navigation by book, chapter, and topic, and light and dark modes. Every chapter page shows the author, edition, license, source link, and source pages. Reference-only books appear as catalog cards that are visibly distinct from mirrored books.
  • R25.Each mirrored book exports to one PDF and one EPUB3 file. Both carry a title page, author and translator attribution, a table of contents, numbered chapters, highlighted code, readable tables, working links, and the license and attribution notice. The PDF has page numbers.
  • R26.A Markdown bundle archive holds the catalog, the metadata, the indexes, and the chapters, license files, and notices of mirrored books only.
  • R27.The site, the PDF, the EPUB, and the bundle are all generated from the same canonical files. No second source tree exists.

Validation, sync, and maintenance

  • R28.One validation command runs offline and checks the schemas, required metadata, the license gate (R5, R6), duplicate ids, chapter order, internal links, topic references, skill exposure, chapter fidelity (R11), and index freshness. It reports each finding with a rule id, a file, a message, and a fix hint, and exits nonzero on any finding.
  • R29.A scheduled upstream check reads each repository's head commit, file tree, license file, and README. It classifies each book as unchanged, changed, moved, gone, or error. It writes an observed-state file and a report, and it opens or updates one pull request. It never edits chapters, license evidence, or mirror status.
  • R30.A failed check for one book changes nothing for that book and does not stop the check of the others. Running the check twice against the same upstream state produces no change.
  • R31.The license gate reads only the evidence recorded for the pinned revision. A license change observed upstream is reported and never changes what the gate allows.
  • R32.The toolchain installs from the lockfile with uv sync, except Pandoc, which is one documented system install whose version the export command checks. Every command prints an actionable message and exits nonzero on failure.
  • R33.The README, the contributor guide, and the maintainer guide let a new engineer run, extend, and maintain the project. They state that this is an independent community project that the author has not endorsed, and they include the license policy and a withdrawal runbook.

Acceptance Examples

  • AE1.Covers R5, R6. Harness Engineering's README says "This work is shared for educational purposes. Please credit the author when referencing." Its status is reference-only, and validation fails if any chapter file appears in its directory.
  • AE2.Covers R5. A book records SPDX MIT but its evidence is a README statement and no license file. Validation rejects eligible for it.
  • AE3.Covers R31. Loop Engineering is mirrored at an MIT revision. Upstream later replaces the license file with CC BY-NC-SA. The sync report says the license changed, the mirrored chapters stay, and validation still passes. The pinned revision cannot move to the new edition while the allowlist excludes its license.
  • AE4.Covers R29, R30. An upstream repository returns 404. The report classifies the book as gone, and no file other than the state file and the report changes.
  • AE5.Covers R18. A document quotes a sentence and attributes it to Hermes Agent, which is eligible and not mirrored. The citation checker fails and names the quote.
  • AE6.Covers R12. The mirrored English edition is v260615 and the newest Chinese edition is v261020. The resolve output for any Loop Engineering chapter says the edition is behind, and AGENTS.md tells the agent to say so when it cites.
  • AE7.Covers R11. A contributor rewrites two paragraphs of a chapter in their own words. The fidelity check fails and names the chapter.
  • AE8.Covers R14. A later edition inserts a section between the third and fourth. The ids of the existing sections stay the same and only their order values change.

Success Criteria

  • A new engineer goes from a clone to passing validation, a built site, and an exported PDF and EPUB using only the documented commands.
  • A coding agent pointed at a clone answers "what does the library say about evaluator design" by citing Loop Engineering section 05. Its citation passes the checker, and it reads AGENTS.md, one index, and at most two chapter files to get there.
  • The owner can verify any book's license classification in about two minutes by opening the recorded permalink and comparing the quote.

Scope Boundaries

Non-goals

  • No database, vector store, embeddings, semantic search, backend API, container runtime, or MCP server.
  • No translation by this project. Only translations the author publishes are cataloged.
  • No mirroring of Chinese editions in this version. The language field exists in the schema.

Considered and not built

  • Aliases for retired chapter ids. No edition has removed a section yet, and validation already names every dangling topic reference in the pull request that removes a chapter. Revisit when an edition upgrade removes or merges a section.
  • A review-status field with a named verifier. An agent can write that field as easily as a person, so it adds no control. The owner's merge is the gate and Git history is the record. Revisit when a second maintainer or a bot identity joins.
  • A list of declined upstream revisions. The sync pull request records observed facts and never adopts them, so merging it acknowledges a change without accepting it and nothing is proposed twice.
  • One sync pull request per book. The single pull request carries facts, not decisions, so one book cannot hold up another.
  • An automated eval harness across agents. The prompts and pass criteria ship as a file and are run by hand before a release. Revisit when a second book is mirrored.
  • Byte-identical PDF and EPUB builds. The freshness check covers the text indexes only.
  • A language model in the scheduled sync job. The job reads untrusted upstream text and holds a write token.
  • Conditional requests with stored ETags. A committed ETag never matches under a different token, so it would make every run change the state file (KTD14). Comparing head commits already limits an unchanged repository to one request, and 12 requests a week is far below the rate limit.

Deferred to Follow-Up Work

  • Ingest Hermes Agent 2.0, which is MIT, English, 104 pages, and cataloged as eligible.
  • Add an HTML source reader, which the Codex book would need if the allowlist widens.
  • Check the listing page for new books and for the seven site-only entries, which no repository poll covers.
  • Commit study artifacts such as quizzes, add a topic-expansion workflow, and package the skills for use in other projects.
  • The owner's own steps: create the GitHub repository, enable Pages, protect the default branch, allow Actions to open pull requests, and ask the author to add license files to the repositories that state terms only in a README.

Open Questions

None of these blocks implementation. Each has a default the plan builds on.

  • Repository and library name. Deferred to the owner. It gates the first push. Every name string comes from one block in catalog.yaml, and the Python package has a neutral name.
  • Admitting CC BY-NC-SA 4.0. Deferred to the owner. Adding it to the allowlist makes no book eligible by itself, because all four books state the license only in a README and R5 requires a license file. They become eligible only if the owner also accepts a README statement as evidence for that license, or the author adds license files. Mirroring them would also need per-book license boundaries inside the combined llms-full file and the bundle.
  • Listing Claude Code Source Analysis at all. Deferred to the owner. The book analyzes leaked source code. The default lists it as reference-only with the third-party flag set.
  • How the default branch is seeded. Deferred to the owner. The repository has no commit on main and the owner's standard forbids committing to it directly.

Planning Contract

Key Technical Decisions

KTD1. Each book has one hand-edited record.

books/<id>/metadata.yaml is the only place a book's facts are written. catalog.yaml holds the library's name and URLs, the license allowlist, the collections, and the ordered list of resource ids. index/catalog.json is the generated join of the two. Two hand-edited copies of a license record would drift.

KTD2. Chapter ids are slugs fixed at first ingestion.

A resource id is a kebab-case slug such as loop-engineering-orange-book. A chapter id is <resource-id>/<section-slug>. The slug is assigned once and never regenerated from the heading or the section number. Chapter files are named NN-<slug>.md so a directory listing shows reading order, and the id leaves the number out. Consumers resolve a path through the index and never build one from an id. This implements R14.

KTD3. One citation token, formatted only by the resolve command.

Documents cite with [cite:<id>], where the id is a chapter id or a resource id, with an optional @<edition> suffix. The human-readable citation string comes only from the resolve command, so every agent prints the same form. The grammar is in the technical design below.

KTD4. The pinned source file of a mirrored book is committed.

It lives at books/<id>/source/ with its SHA-256 in the metadata. Ingestion, the fidelity check, and edition diffs then run offline in CI, and the mirror survives an upstream force-push or deletion. The cost is about 1 MB of binary per edition. A cache fetched by URL was rejected because it would make the fidelity check depend on the network.

KTD5. PDF text is extracted with pypdf and classified by font size.

A visitor collects spans of text with font size, position, and page. A per-book profile in the metadata maps a size and a left indent to a role. The book has no diagrams. pypdf 7.1.1 reports these sizes for the Loop Engineering PDF:

  • 24.0 for the section label such as §03, which is a span of its own.
  • 26.7 for the section title, which wraps to a second line in four sections.
  • 15.3 for the lede paragraph under each title.
  • 17.3 for a subsection heading and 14.0 for body text.
  • 13.3 for two things: the quote callouts, which are indented, and the one-line kicker under each section title, which sits at the body margin.
  • 11.3 for a table header and 12.7 for a table cell.
  • 12.0 for code, which no other text in the sections uses.

The reader that turns a PDF into spans is thin. The stages that turn spans into blocks and blocks into Markdown are pure functions, so tests feed them spans built in memory. pymupdf4llm was rejected for its AGPL license, Docling and marker for their machine-learning dependencies, and poppler for being a system binary.

KTD6. Ingestion never overwrites a chapter.

Drafts go to the ignored directory build/ingest/<id>/. The --write flag copies only chapter files that do not exist yet. An existing chapter is changed by hand, guided by the diff that ingestion prints between the draft and the committed file.

KTD7. Fidelity is exact on words and bounded on order.

The check strips Markdown markup from the chapter body, extracts the chapter's page range from the committed source file, and normalizes whitespace and punctuation variants in both. It then applies two rules. The two texts must contain the same words the same number of times, so one changed name, one flipped number, or one dropped word fails. Their word order must also score 0.98 or higher on sequence similarity, which leaves room for a table or a callout repaired into reading order.

A word that a repair restores or removes must be listed in the book's profile with its chapter, the words, and a reason. Validation prints that list. A similarity floor alone was rejected because 0.98 lets about 20 to 30 words change in a section of 1,000 to 1,600 words. The check runs inside validation. This implements R11.

KTD8. Each chapter states how far its review has gone.

Extraction status is machine-extracted or human-reviewed. The site, the PDF, and the EPUB show a notice on a machine-extracted chapter. Chapters land as machine-extracted, and only a person who has read one against the source changes its status.

KTD9. Small indexes are committed and full text is published.

index/catalog.json, index/topics.json, index/chapters.jsonl, and llms.txt are committed, and validation fails when they are stale. That satisfies R15. The llms-full files, one per mirrored book and one combined, are written to dist/ and published with the site. Keeping them out of the clone means a text search returns each passage once.

KTD10. The two read commands use only the standard library.

scripts/resolve.py and scripts/check_citations.py read the committed indexes and import nothing outside the standard library. They and their shared module are written to run on Python 3.9, which is the python3 that macOS ships, so an agent can call them before anything is installed. On an older interpreter they print the required version and exit nonzero. They find the repository from their own file path, so an agent working in another project can call them against a clone. Text search and topic lookup stay plain rg.

KTD11. Skills have one canonical copy and a link for Claude Code.

Each skill is a folder at .agents/skills/<name>/ with a SKILL.md whose frontmatter uses only name and description. Codex and Cursor read that location. Claude Code reads only .claude/skills/, so each skill has a relative symlink there. Validation asserts that both directories expose the same set.

CLAUDE.md is the single line @AGENTS.md. A prose pointer would make Claude Code load one sentence and skip AGENTS.md. These facts were read from the vendors' documentation on 2026-11-20. Whether Cursor lists a skill twice when it finds it in both directories is not documented and is a manual check.

KTD12. The site builds from a staging directory.

build.py assembles build/site-src/ from the canonical files plus generated pages: a page per book, a card per reference-only book, and an attribution block on each chapter. MkDocs Material 9.8.2 on MkDocs 1.6.1 builds from that directory. Canonical files are never edited for the site.

KTD13. PDF goes through Pandoc to Typst. Typst is a wheel and Pandoc is a system tool.

Pandoc writes Typst markup through a small template, and Typst compiles the PDF. Pandoc also writes the EPUB3. No LaTeX distribution is needed. typst 0.15.2 ships a native binary inside its wheel for macOS arm64 and Linux x86-64, so the lockfile pins it.

Pandoc cannot come the same way. The pypandoc-binary 1.17 wheel tagged for macOS arm64 contains an x86_64 binary, and the owner's Mac has no Rosetta. Pandoc is therefore installed once per machine: with Homebrew on macOS, and from the official release package in CI at the same version, 3.14. The export command finds pandoc on the path, checks it against a minimum version kept in one place, and names the install command when it is missing. This implements R32.

KTD14. Sync is plain Python with pinned and observed state kept apart.

The metadata holds what is pinned. upstream/state.json holds what upstream last showed. A repository whose head commit equals the observed one costs one request, and nothing else is read from it. ETags are not stored, because GitHub computes them per credential, so an ETag committed from one token never matches the next run's token and the file would change on every run. upstream/report.md is the change report and contains no timestamp, so the same upstream state always produces the same bytes. The workflow pushes one fixed branch, sync/upstream.

A pull request opened with the workflow's default token does not trigger other workflows. The sync workflow therefore runs validation and the tests on the proposed tree itself before it opens the pull request.

KTD15. Editions are detected by filename pattern and blob SHA.

Each book declares one filename pattern per language with a capture group for the version. Sync compares Git blob SHAs from the tree listing, so new bytes under an old filename are caught. A file that matches no pattern is reported as unclassified and never proposed as an edition. For README terms, sync checks that the recorded statement still appears and reports when it does not. It never infers permissions.

KTD16. Scripts are thin entry points over one typed package.

Shared code lives in the package scripts/kb/. Each file in scripts/ parses arguments and calls it. Records are dataclasses built after JSON Schema validation. mypy runs in strict mode and ruff lints and formats. Tests live under tests/, which follows the requested layout and Python convention. The owner's global standard prefers tests beside the code, and the requested structure wins here.

High-Level Technical Design

Components and data flow

Ingestion reads a pinned upstream PDF and writes canonical chapter files. Validation and the license gate check the canonical files and every generated output.

Mirror status lifecycle

A mirrored book whose upstream license later changes stays mirrored at its pinned edition, per R31.

Id and citation grammar

resource-id   = slug                          ; loop-engineering-orange-book
chapter-id    = resource-id "/" slug          ; loop-engineering-orange-book/five-moves-of-one-loop
edition       = 1*( ALPHA / DIGIT / "." )     ; v260615
cite-token    = "[cite:" ( chapter-id / resource-id ) [ "@" edition ] "]"
slug          = 1*( lowercase / DIGIT ) *( "-" 1*( lowercase / DIGIT ) )

chapter file  = books/<resource-id>/chapters/<NN>-<slug>.md
formatted     = Author, "Title" (English ed. v260615), section label "Section title",
                source PDF pp. 9-12. [cite:<chapter-id>@v260615]

A chapter token is valid only for a mirrored book. A resource token is valid for any cataloged book and resolves to its official link when the book is not mirrored. A token with no edition means the edition currently mirrored.

Risks and Dependencies

  • Extraction order and tables. pypdf emits inline bold text as separate spans and does not guarantee reading order, and tables must be rebuilt from x positions. The fidelity check catches loss and edits made after extraction. It cannot see text that pypdf itself drops, which U6 covers with one comparison against a second extractor, and chapters stay marked machine-extracted until a person reviews them (KTD8). The book has 36 pages, so a table that will not reconstruct is repaired by hand, which R11 allows.
  • Font names in pypdf. The PDF uses Type 3 fonts and pypdf returns no base font name for them. The profile therefore identifies code by its size, which no other text in this book's sections uses. A later book that sets code at a body size would need another signal.
  • The misattributed quote. Upstream says the Chinese v261020 edition lists errata for the June edition, including a quote wrongly attributed to Addy Osmani. Recording it under R12 needs the passage identified from the Chinese note to readers. If it cannot be identified with confidence, the book carries one notice that the English edition predates those errata, and no chapter-level entry is guessed.
  • Pandoc and Typst together. Planning did not compile the Typst markup that Pandoc 3.14 writes under Typst 0.15.2, because Pandoc was not installed. U11 proves the pair before it builds the template, and a stop condition covers a mismatch.
  • CJK glyphs in the PDF. The author's name includes 花叔. The Typst wheel bundles no CJK font. CI installs Noto CJK and the template lists it with macOS system fonts as fallbacks. A missing glyph renders as a box without failing the build, so the export test reads the name back from the PDF.
  • MkDocs versions. MkDocs Material 9.8.2 was released on 2026-11-19, and MkDocs core has had no release since 1.6.1 in August 2024. Both are pinned. A reviewer's sample build showed Material 9.8.2 printing an end-of-life notice dated 2027-05-05 that names Zensical as its successor. The staging directory is plain Markdown, so another site generator could read it.
  • Prompt injection from mirrored text. The books contain sample prompts and agent instructions. R19 covers the instruction to agents, and no mirrored text is placed in a file that an agent loads automatically.
  • A single maintainer. Branch protection cannot make the owner review their own pull request, and a local agent commits under the owner's identity. The control is that nothing pushes to the default branch and the owner performs every merge. The maintainer guide says this plainly.
  • Scheduled workflows. GitHub disables a schedule in a public repository after 60 days without activity. The maintainer guide tells the owner how to re-enable it.
  • Skill packaging drift. The locations each agent reads were verified on 2026-11-20 and vendors change them. Validation checks that the two skill directories match, and the manual check in U9 covers discovery.

Approach

  • The test fixture PDF is compiled from sample-book.typ with the Typst wheel in a session fixture, so no binary fixture is committed and its font sizes are known.

U12. Upstream sync

Goal
The owner learns about a new edition, a new translation, or a license change from a pull request, and nothing changes without them.
Requirements
R29, R30, R31
Dependencies

Files, approach, tests, and verification

Files

  • Create scripts/sync.py, scripts/kb/sync.py
  • Create upstream/state.json, upstream/report.md
  • Create tests/test_sync.py and recorded responses under tests/fixtures/github/

Approach

  • Follow KTD14 and KTD15. For each book with a Git source, request the head commit. When it equals the observed commit in the state file, record unchanged and make no further request.
  • On a new head, read the tree, the license file, and the README. Compare them with the metadata and derive findings: a new edition file, new bytes under a known filename, a file in a new language, an unclassified file, a changed or missing license file, a recorded README statement that no longer appears, or a repository name that differs from the catalog.
  • Classify each book as R29 lists. A 404 is gone. A rate limit, a server error, or a timeout is error, and the book keeps its previous state entry.
  • Site-only books are listed in the report as not checked.
  • Write the state file with sorted keys. Write the report grouped by classification with no date in it.
  • The command writes only under upstream/. --dry-run prints the report and writes nothing. The exit code is nonzero only when every book ends in error.

Test scenarios

  • An unchanged head commit for every repository leaves both files byte-identical and makes one request per repository.
  • A new head with an unchanged tree updates the observed commit and reports the book as unchanged.
  • A new file that matches the English pattern with a higher version is reported as a new English edition.
  • A known filename with a different blob SHA is reported as changed bytes.
  • A file that matches the pattern of a language the book did not have is reported as a new translation.
  • A file that matches no pattern is reported as unclassified.
  • Covers AE3. A license file with a different blob SHA is reported as a license change, and no file outside upstream/ changes.
  • A README that no longer contains the recorded statement is reported as statement not found.
  • Covers AE4. A 404 classifies the book as gone and leaves its metadata untouched.
  • A 500 for one repository classifies it as error, keeps its previous state entry, and still processes the other books.
  • A 403 with rate-limit headers classifies the remaining books as error and exits zero when at least one book succeeded.
  • A response whose repository full name differs from the catalog classifies the book as moved.
  • Running twice on the same recorded responses produces no second change.
  • --dry-run writes no file.
